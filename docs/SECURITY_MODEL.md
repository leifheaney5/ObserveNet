# Security model

How ObserveNet protects itself and the data it holds, and what it deliberately refuses
to do. This describes the implemented controls; it is not a claim of production
readiness and has not been independently reviewed.

## What ObserveNet refuses to do

- No exploitation, exploit chains, payloads, brute force or credential guessing.
- No intrusive or third-party scanning. No port scanning of other devices. The only
  packets it originates are: ICMP echo to approved private addresses, TCP handshakes to
  an allowlisted port set, DNS lookups, and — if opted in — a bounded HTTPS download and
  a low-rate ICMP sweep of approved private ranges.
- No packet capture or interception.
- No remote control: it never reboots devices, edits router/firewall configuration,
  blocks clients or kills services. Remediation steps are text for a human to run.
- The agent executes nothing the backend sends. Server-provided configuration is limited
  to intervals and probe targets, which the agent re-validates.
- Findings never claim exploitability. Classifications are `OBSERVED_CONFIGURATION`,
  `POTENTIAL_EXPOSURE`, `VERIFIED_RESOLUTION`.

## Authentication

### Users (browser)

- Passwords hashed with **Argon2id** (`argon2-cffi` defaults, RFC 9106 low-memory
  profile); rehash on login if parameters change. Minimum 12 characters; known
  placeholder passwords are rejected.
- **No default credentials.** The first admin is created from
  `OBSERVENET_ADMIN_PASSWORD` (generated by `make init`) or with
  `python -m observenet.cli create-admin`. If neither is done, no account exists and
  login is impossible.
- Sessions are opaque random tokens (256 bit). Only an HMAC-SHA256 digest keyed with
  `OBSERVENET_SECRET_KEY` is stored (`sessions.token_hash`). Server-side state means
  sessions can be revoked: logout, password change (revokes the user's other sessions),
  disabling a user.
- Cookie `observenet_session`: `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` when
  `OBSERVENET_PUBLIC_URL` is `https://` (or `OBSERVENET_COOKIE_SECURE=true`).
  Lifetime `OBSERVENET_SESSION_TTL_HOURS` (default 12).
- **CSRF:** every non-GET request authenticated by cookie must send
  `X-CSRF-Token` equal to the token stored in the server-side session (also available
  from `GET /api/v1/auth/me` and the non-HttpOnly `observenet_csrf` cookie). Compared in
  constant time. GraphQL POSTs require the same header; GraphQL over GET is disabled.
- Login rate limit: 8 attempts per minute per client IP (Redis counter; degrades to a
  per-process counter if Redis is down). Unknown usernames still run a hash
  verification to keep timing similar. Failed logins are audited.

### Collectors (agents)

- Bearer tokens with prefix `onet_`, 256 bits of entropy. Only the keyed digest is
  stored; the raw value is shown once at creation.
- Scope `ingest` only: a token can call `POST /api/v1/ingest/agent` and
  `GET /api/v1/agent/config`, nothing else.
- **Bound to one agent:** the first batch binds the token to that `agent_uid`; a
  different agent presenting the same token gets 403.
- Expiry (default 90 days, `OBSERVENET_AGENT_TOKEN_TTL_DAYS`) and immediate revocation
  (Settings → Tokens, `DELETE /api/v1/tokens/{id}`). No caching of token lookups, so
  revocation takes effect on the next request.
- The bundled collector uses `OBSERVENET_BOOTSTRAP_AGENT_TOKEN` from `.env`. It is
  registered once at startup and has no expiry; if revoked it stays revoked. Rotate it
  by issuing a new token in the UI and updating `.env`.
- Per-token ingest rate limit (default 240 requests/min).
- The Linux agent refuses to send its token over plain HTTP to a non-loopback host
  unless `OBSERVENET_ALLOW_PLAINTEXT=1` is set explicitly.

## Authorization

| Role | Can |
|---|---|
| `admin` | Everything |
| `viewer` | All read endpoints; every mutation returns 403 |
| agent token | Ingest + own config only |

Enforced per route with FastAPI dependencies (`auth/deps.py`): `CurrentUser`,
`AdminUser`, `AgentToken`. Exports, the audit log, tokens, users and deployment facts
are admin-only. The last active administrator cannot be demoted or disabled.

GraphQL: no valid session → HTTP 401 before execution; every root field also carries an
`IsAuthenticated` permission; `Device.auditTrail` requires admin.

## Unauthenticated surface

Exactly three endpoints answer without credentials:

- `GET /api/v1/health` — static liveness.
- `GET /api/v1/ready` — dependency status (`ok` / error class name), no data.
- `GET /api/v1/meta` — product name, version, `demo_mode`, `setup_required`.

Everything else, including the WebSocket, GraphQL and all inventory, requires a
session. OpenAPI/Swagger and GraphiQL are served only when `OBSERVENET_ENV=development`.

## Transport and browser hardening

- **TLS** is terminated at the edge (Cloudflare Tunnel in the documented deployment).
  The stack itself listens on `127.0.0.1` over HTTP; it must not be published directly.
- **Trusted hosts:** requests whose `Host` is not in `OBSERVENET_ALLOWED_HOSTS` are
  rejected.
- **No CORS middleware:** the SPA is same-origin, so browsers refuse cross-origin reads.
- **WebSocket:** the `Origin` header must match the public origin or the request host,
  the session cookie is checked at the handshake and re-checked every 60 s.
- Response headers on every response: `Content-Security-Policy` (`default-src 'self'`;
  scripts self only; inline styles allowed for the chart library; `frame-ancestors
  'none'`), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: same-origin`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`,
  `Cache-Control: no-store` on API responses, and HSTS when cookies are `Secure`.

## GraphQL hardening

Read-only schema; query depth limit (`OBSERVENET_GRAPHQL_MAX_DEPTH`, default 8); at most
15 aliases and 2000 tokens per document; page size capped at 100; keyset cursors;
introspection disabled in production (`OBSERVENET_GRAPHQL_INTROSPECTION` overrides);
no GraphiQL in production; batched loaders so query fan-out is bounded.

## Network exposure of the stack

- Only `web` (nginx) publishes a port, bound to `127.0.0.1` by default.
- PostgreSQL, Redis and the API port are reachable only on internal Docker networks.
- **Prometheus metrics** are served by a separate listener
  (`OBSERVENET_METRICS_PORT`, 9464 in Compose) inside each process. It is not part of
  the HTTP application, so the reverse proxy and the tunnel cannot route to it.
- The Docker socket is never mounted into ObserveNet containers. The optional
  `docker-inventory` profile uses a socket proxy limited to the container list.
- The collector container: non-root, read-only root filesystem, all capabilities
  dropped (`NET_RAW` optional for ICMP), host network namespace (required to see the
  host's interfaces and sockets).

## Input validation

- All request bodies are Pydantic models; ingest models use `extra="forbid"`, bounded
  list sizes and string lengths, known metric names with fixed units, finite floats.
- Probe targets and discovery ranges pass `services/netscope.py` (see
  `TELEMETRY_SOURCES.md`); the agent re-validates.
- History queries: bounded range (≤ 366 days), allowlisted bucket widths, ≤ 1500 points.
- Client-list import: size cap, row cap, private addresses only.
- SQL goes through SQLAlchemy with bound parameters. The two dynamic DDL statements
  (partition create/drop) build names from a date and a regex-validated catalog name.

## Secrets

| Secret | Where | Notes |
|---|---|---|
| `OBSERVENET_SECRET_KEY` | `.env` | Keys the session/token digests. ≥ 32 chars enforced in production. Rotating it invalidates all sessions and agent tokens. |
| `OBSERVENET_ADMIN_PASSWORD` | `.env` | Used once to create the first admin; can be removed afterwards. |
| `OBSERVENET_BOOTSTRAP_AGENT_TOKEN` | `.env` | Bundled collector token. |
| `POSTGRES_PASSWORD` | `.env` | Database password on the internal network. |
| `CLOUDFLARE_TUNNEL_TOKEN` | `.env` (only with the `tunnel` profile) | Grants the ability to serve the tunnel's hostname. |
| Webhook secret | `.env` (optional) | HMAC-SHA256 signature header on alert webhooks. |

`.env` is git-ignored. The structured logger redacts fields whose name contains
`password`, `token`, `secret`, `authorization` or `cookie`. Exports contain inventory
and findings only — no tokens, hashes or sessions. Token values are never returned by
any API after creation.

## Audit

`audit_events` records actor, action, target, client IP and details for: logins
(success and failure), logout, password changes, user changes, token create/revoke,
source changes and tests, device edits, merges/unmerges, imports, finding actions and
verification requests, alert actions, alert-rule and maintenance-window changes, probe
target changes, settings changes and exports. Read via `GET /api/v1/audit` (admin).

## Privacy

- Inventory data (MACs, IPs, hostnames) stays in the local PostgreSQL volume.
- No analytics or telemetry is sent to any third party.
- Outbound connections by default: TCP handshakes to 1.1.1.1:443 and 9.9.9.9:443 and a
  DNS lookup of `example.com` every 30 s (all configurable or removable); OTLP export
  and alert webhooks only if configured; the tunnel only if enabled.
- The agent identifies itself with a random id; when it has to derive one from
  `/etc/machine-id` it sends a hash, not the machine id.

## Known gaps

See `THREAT_MODEL.md` (residual risks) and `LIMITATIONS.md`. Notable: no MFA in the
application (rely on the edge access policy), no encryption at rest beyond what the
host provides, no OIDC integration, single shared database role.
